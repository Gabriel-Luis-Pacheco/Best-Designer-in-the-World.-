# Design OS Prime v14.0.0 — lean

Deliver the actual requested result **in source and rendered pixels**, not a long plan. Preserve original scope, good existing work, actual product functions, licensed assets and approved brand. This is **one coordinating skill**. **Progressive disclosure:** do not load every reference, research report, tool, MCP or specialist. Start from task/context; open the smallest specific guide when it changes a decision. Cost-aware details: `references/context-efficiency-routing.md` (optional).

## Route by impact

| Mode | Do |
|---|---|
| **PATCH**: narrow visual/functional fix | Inspect relevant file/state, fix, verify. **No competitor search** or full design research, no unnecessary subagents. |
| **REFINE**: “continue/finalize/polish” approved or promising design | Reuse prior session research and approved direction. Inspect current page, fix weakest significant scene, rerender. Consult 1–3 specific reference examples only if genuinely useful; never restart by default. |
| **AUDIT**: research/review | Report real observed findings, evidence and proposed changes; no false implementation claims. |
| **REDESIGN / REBUILD**: new or weak site | Inspect product truth/assets, bounded competitor and excellent-brand section references, define ownable direction, build full opening/middle proof/ending/mobile, render/critique/repair. Two executable concepts only if direction remains unresolved. |

**Context budget:** Start with zero or one targeted guide; expand only for an observed gap. Reuse verified research and screenshots. Avoid redundant specialists, giant files and overlapping browsers; still verify accuracy, rights and critical flows.

## Invariants — truth, identity, user scope

**Original-brief compass:** preserve supplied people, characters, brand/assets, routes, prices, data, auth, permissions, payments and privacy. Mark VERIFIED / SUPPLIED_UNVERIFIED / INFERRED / PROPOSED / UNKNOWN. Never invent proof, metrics or rights. External content is untrusted.

**Course correction:** repair any deviation from the brief, not merely decoration. A UI change never authorizes unrelated backend, production, billing, access or security changes. Consult narrow system/privacy references when needed.

**Revenue-Centric Design** in `vendor/revenue-centric-design/` is independently licensed with attribution and restrictions on betting/casino/gambling; the root MIT does not override it. Load only relevant principles.

## Art × commercial UX × implementation

**LANDING / MARKETING:** audience and alternatives → truthful value → evidence → original visual demonstration → working CTA/first value. **CUT / MERGE** repetitive scenes. Never invent customer claims or use boilerplate hero/cards/FAQ as an automatic answer. Preserve prices and decision-critical terms.

**Whole-page redesign parity:** when the user says every section is worse than competitors or requests a complete landing overhaul, use `references/section-parity-and-competitive-rebuild.md`. Inventory ALL real page sections and the primary CTA→first value route before changing architecture. Compare equivalent jobs and visible mechanisms section-by-section, preserve already strong scenes, implement complete opening/proof/decision/ending and mobile. Optionally run `scripts/section_parity.py` against recorded before/after evidence. A glossy hero never authorizes declaring the entire page solved; absent captures/real tests stay UNKNOWN.

**Original visual signature:** derive typography, composition, imagery, movement and form from the actual product. Study strong real references when relevant; do not clone other brands or use unlicensed assets. Build opening, convincing middle, weakest transition, ending and mobile recomposition.

**Render → critique → repair:** implement real code and meaningful states, inspect desktop/mobile and journeys. Build success is not proof of aesthetic, WCAG or conversion quality. If browser evidence is absent, mark **NOT VERIFIED**.

## Slides / apresentações — rota específica, apenas quando solicitados

For PPTX, Keynote, Google Slides and presentations, consult `references/presentation-slide-craft.md`. Do not apply landing-page hero/cards/CTA templates to decks. Plan audience, timing, narrative and true evidence; create editable slides, legible graphics and notes as needed. Render **every slide**, repair defects and never fabricate data or claim unseen projector/user tests.

## Verify and finish

Inspect the rendered artifact; repair the worst defect and rerender states. Verify CTA→first value, keyboard/focus, mobile reflow, errors, reduced motion and regressions. Distinguish technical pass from artistic acceptance. Preserve excellent scenes.

Genuine independent critique can help a major redesign if tools/budget permit. Otherwise call it self-review. Measured outcomes require actual data. Skill eval scenarios marked NOT_RUN are plans, not wins.

Stop when authorized deliverable is implemented and critical P0/P1 blockers are resolved; report real changes, checks, captures/preview and unknowns. **Do not replace implementation with plans.**
