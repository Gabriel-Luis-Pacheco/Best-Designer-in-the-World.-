# Award-readiness & visual QA — rigorous without self-awarded trophies

Load on high-ambition REDESIGN/REBUILD or any task expressly seeking an Awwwards-level experience. It complements, not replaces, references/quality-gates-and-evidence.md and the human rubric. No AI model can self-certify an award.

## Evidence packet — collect before a 'finished' claim
1. Product truth/approved brand identity and contract constraints; licensed and canonical visual assets.
2. Creative intent with explicit signature: formal/material/behavioral and product meaning.
3. Navigation map or storyboard (opening, transformations, middle, interactive climax, closure, mobile adaptation).
4. Real full-page screenshots plus scene-specific captures at settled, pinned and interactive states. Separate 320/390/768/1440 and practical orientation as relevant.
5. Real browser interactions: CTA, form, keyboard, focus, links, scroll down/up, touch, zoom, system reduced motion, loading/error/empty states.
6. Build/deployment logs, runtime console/network errors, relevant automated tests and field/lab performance measurements where available.
7. Asset provenance and rights, model/textural optimization steps where relevant, versioned before/after and known limitations.

## Five separate assessments — not one magic number
- **Visual craft**: original hierarchy, typography, silhouette, material quality, section-to-section change, composition at multiple scales.
- **Creative mechanism**: could the central gesture/visual law be transplanted to an unrelated project? Does it have memorable stakes and payoff?
- **Product UX**: recognition, comprehension, accessibility, trust, task/CTA completion and error recovery.
- **Technical reliability**: asset loads, SSR/hydration where present, lifecycle cleanup, bundle/frame consistency, failures, browser compatibility.
- **Content integrity**: useful story, sourced claims, licensed media, language that says something concrete.

Do not weight these as if they are official juror grades. Historic Awwwards weights are background only. A blocking P0/P1 takes precedence over any artistic average.

## Render → diagnose → correct
- Challenge the WHOLE visual journey: an exceptional hero does not cancel generic middle; any repeated heading-card-feature sequence is a candidate for rebuild.
- Produce an independently useful worst-link diagnosis with location, screenshot/state, causal explanation, proposed correction and expected benefit.
- A fresh reviewer should be able to identify product/task, distinguishing signature and next action without reading the author’s intent.
- For substantial creative projects, do two credible view-and-fix passes when feasible: first fix structural causes, second polish and recheck. Do not waste rounds on colors if concept is the issue.
- Record what stayed strong and preserve it. Never flatten everything to one safe design system.
- If browser/tools missing, mark NOT_VERIFIED; tests can validate implementation but never prove artistic excellence.

## Fair skill-vs-no-skill trials
Same input brief, assets, model, budget, tool permissions, runtime and independent workspaces. Verify that the named skill truly loaded; baseline must not secretly load a competing design skill. Compare actual outputs blindly, randomize review order, repeat across varied briefs/surfaces. Record both wins and losses. If sample insufficient, state descriptive result without certainty or guarantees.
