# Context efficiency and on-demand guidance

**Read only for optimization, expensive orchestration, or ambiguity in routing.** Short `SKILL.md` is authoritative.

## Economics and caveats
A larger skill entrypoint, references, website captures, tool outputs and subagent transcripts all consume context when loaded; context caching can affect billed tokens but does not guarantee smaller effective context. Reducing the entrypoint is a structural improvement, not measured total-cost savings. Record real model usage before claiming monetary savings.

## Progressive disclosure by mode
- PATCH: affected code/state only, verify changed behavior. No galleries, no competitors, no research council.
- REFINE / continue: current render and prior approved direction first. Reuse existing session findings and screenshots. If the design gap needs outside inspiration, inspect a small targeted set of section scenes; never rerun full research or rebuild the hero just to comply with a ritual.
- AUDIT: evidence-first; separate OBSERVED/INFERRED/HYPOTHESIS/UNKNOWN; no claimed edits.
- REDESIGN: real product facts and canonical media; targeted competitors/beautiful brands; build representative full-page scenes early, render desktop/mobile, refine weak causes. Two alternative directions only if no coherent direction chosen.
- REBUILD: add actual route/state inventory, ownership, recovery and proportionate critical UX/security/brand QA.

Research/skills/MCP calls are chosen **because they change an implementation decision**, not because they are listed. One browser can often inspect reference pages and the live product. Don't call multiple generic specialists for the same issue; only use available installed tools, not imagined integrations. Never send private app secrets to third-party MCPs.

## Stop condition
Stop research when further reading is unlikely to improve a concrete decision; stop polishing after actual P0/P1 deficiencies within scope are resolved and strongest creative options are implemented. Run real checks for significant visual tasks; label unavailable checks UNKNOWN. Log optional source/date observations only where they prevent repeat work. Avoid a documentation warehouse for a one-button change.
