# Original brief compass and exact reference identity

Use for every REDESIGN/REBUILD and for any PATCH that changes an explicitly named entity, scene, asset, product action or material requirement. This is a **practical production safeguard**, not a user-facing questionnaire or excuse for long planning.

## The hierarchy of intent

1. **Original user brief and explicit amendments** remain the source of authority. Save its exact wording before extracting assumptions.
2. **Non-negotiable requirements**: explicitly named subjects/characters/people/brands, recognizable identity, sequence or interaction, platform/stack constraints, rights, assets, route behavior, existing brand canon and requested deliverables. A creative improvement cannot silently discard these.
3. **Preferences and goals**: emotional tone, quality ambition, recognizable references, audience, first value, cinematic direction. Interpret these through authentic evidence, not a generic style template.
4. **Reversible design choices**: typography, crop, choreography, motion stack, spacing, visual motif and component structure. Decide proactively where allowed.
5. **Unknown facts or permissions**: research with available authorized tools or mark UNKNOWN. Never fill gaps with invented product behavior, unlicensed assets, fabricated metrics or a lookalike presented as the named original.

The user owns *what* must be made and hard boundaries. The agent owns *how* to make it superb. When creative freedom and a protected reference conflict, preserve the reference and improve the execution **around** it.

## Resolve named references before visual production

When the prompt names a proper noun that represents a visual subject, brand, artifact, product, specific scene, work, animation style, fictional character or cultural reference:

1. Extract the complete name and relationship from the original wording; preserve spelling and qualifiers. Do not guess from an ambiguous short name.
2. Identify the requested role: **exact subject**, **inspiration only**, **official brand asset**, **behavior/scene homage**, **source screenshot**, or **original concept**. These are not interchangeable.
3. Resolve identity from user-supplied assets first, then official/authoritative sources when available. Record the canonical title/context, distinguishing features, allowed asset, source link or file path and confidence. If unresolved, never mark MATCHED. Ask a focused question only if indispensable; otherwise progress independent sections and clearly flag the blocked asset.
4. Check actual rights and intended use separately from recognition: finding an image online does not authorize commercial reproduction. Use licensed/user-authorized materials or a legitimate original alternative **only with explicit agreement when it changes a must-have**. Do not pretend that an unapproved replacement meets a character-specific brief.
5. Produce a real visual asset or compatible implementation using available tools. Do not substitute a text description, emoji, stock photo, near-name, generic person or unrelated silhouette for the required specific subject.
6. Review the output **at the intended viewport and animation state**, against canonical identity anchors. Verify shape, costume, colors, material details, role, timing, recognizability, and requested actions. A model saying “the subject is correct” is not evidence.
7. Mark identity as MATCHED / MISMATCHED / UNVERIFIED / NOT_RENDERED. MISMATCHED must cause correction before release. UNKNOWN cannot become PASS by repetition.
8. If legal rights, source access or production tools prevent exact delivery, disclose the limitation and preserve the request as unmet. Never silently solve it by changing the character.

## Three brief checkpoints (lean, internal)

- **Direction:** re-read the literal original prompt; map each must-have to a planned scene, asset, state or function. Protect original assets and real product routes.
- **First render:** inspect the actual opening, strongest mid-page section, closing, mobile and key interactive state. Compare with each must-have, not with the builder's updated story. An impressive opening can still fail if the requested subject, content or service flow is absent.
- **Before handoff:** re-open the original prompt, check implementation and diff, rerun critical interactions, asset recognition, mobile and SEO (public sites). Identify unmet MUSTs, regressions and unapproved substitutions. Fix the causal failure and rerender.

Optional portable contract: `scripts/brief_alignment.py` requires explicit requirements, exact referents, three checkpoints, evidence and stated deviations. It **validates declarations**, not visual similarity or publication rights. Small PATCH and AUDIT need proportionate review, not three mandatory full-screen production cycles.

## Backtracking triggers

Return to concept or architecture—not cosmetic polish—when:
- the requested named identity or central interaction is absent, generic or inconsistent;
- the real product/service is still not legible in the hero and main action;
- the opening is impressive but the middle/ending are repetitive or unfinished;
- the project drifts into a different audience, offer, tone or kind of site;
- a critical click, payment, data or navigation path stops working;
- reviewers disagree about the basic purpose or the customer would not understand why this exists.

Keep the original objective visible in every correction cycle. Propose and choose stronger execution; **do not change immutable requirements under the guise of proactivity**.

## Ambition without false guarantees

A vague brief is a cue for *more professional initiative*: research, distinctive concept, actual media, coherent site-wide composition, better first-frame, satisfying interactive payoff, conversion clarity and finished responsive details. At the end, consider one meaningful “stretch” improvement that elevates the whole experience without violating constraints. Do not add unnecessary sections, 3D, SEO pages, animations or invented functionality to prove effort. Exceptional quality is a goal evidenced in output, not guaranteed by instruction length.
