# Proactive senior-design coverage — do the necessary invisible work

The user often asks for “make me a great site,” not for an exhaustive agency brief. Proactivity means **doing necessary professional discovery and finishing work without shifting the workload to the user**, while protecting real facts, rights, privacy, scope and time. This checklist is internal decision support, not a page template or paperwork to dump into the answer.

## Automatic scan — activate by product surface

| Context | Inspect proactively | Do not invent or force |
|---|---|---|
| New marketing site | Positioning, real alternatives, audience language, differentiated proof, headline/CTA, full page narrative, mobile, public SEO, share previews | Fake testimonials, exaggerated metrics, auto-generated SEO pages, arbitrary urgency |
| Service portfolio / art | Real work/credits/media, requested exact identity, narrative and visual signature, project cases, working contact, motion accessibility, permissions | Generic actor replacing a named subject, unusable 3D barrier, fake client logos |
| SaaS onboarding/product | Real first-value path, meaningful task UI, orientation, empty/loading/error/success, duplicate flow owners, progressive disclosure, mobile and consent | Extra onboarding hoops, fake product UI, unapproved backend changes |
| Commerce | Honest total price, variants, shipping/returns where applicable, availability and checkout recovery, clear trust context | Hidden charges, mock payment buttons, unapproved plans or inventory |
| Internal / analytics | Data provenance, density, exact labels, affected routes, filtering correctness, permissions and error recovery | Awwwards theatrics, fabricated KPI stats, SEO marketing |
| Documentation/READ | Accurate concept taxonomy, findable navigation, examples, source freshness, search and keyboard | Artificial conversion funnels, thin templated “SEO articles” |
| Global/public launch | True favicon/logo, domain, semantic language, metadata/OG, indexability, canonical/sitemap as appropriate, analytics/privacy, error route, LCP/INP/CLS, mobile | Ranking guarantees, unverified analytics consent, invented legal text |

## The under-the-hood passes

1. **Original request:** retain verbatim; extract named referents, immovable constraints and success criteria. Do not replace an exact subject with an approximate one.
2. **Product reality:** inspect current routes, code, provided assets, real product behavior, price, permissions, content and what visitors can actually do.
3. **Positioning:** establish what it is, for whom, alternatives, specific differentiation and reason to trust it. If unknown, avoid made-up promises.
4. **Research:** inspect a small number of relevant high-quality references and current official docs when useful. Learn their mechanisms; never clone their visual identity or copy.
5. **Art concept:** create at least two materially different directions for an unsettled rebuild, choose by fit and evidence, not preset palette; produce a recognizable visual signature.
6. **Asset production:** find authentic approved footage/images/characters/fonts and create suitable originals when authorized and tools allow. Avoid generic image placeholders disguised as final.
7. **Copy:** clear truthful first frame, microcopy, CTA, objections, local language and brand character; text and visual proof should reinforce each other.
8. **Design beyond the hero:** opening, purposeful middle, meaningful ending/CTA, real mobile and state coverage; cut repeated sections.
9. **Interaction:** animation should change perception, explain an action or create an earned emotional climax; avoid random parallax, scroll traps, multiple competing motion engines.
10. **Accessibility:** semantic structure, focus, keyboard, touch, zoom, labels, reduced motion, contrast, meaningful error and recovery; do not treat good taste as WCAG compliance.
11. **Search (only when public):** useful URL map, page-specific title/description, canonical, real crawlable links, indexing settings, imagery, share previews, performance; test deployed behavior when available.
12. **Truth and rights:** protect product values, brand canon and licensed media. Public examples and fictional characters may still be subject to copyright/trademark rules; recognition is not proof of permission.
13. **Engineering:** error boundaries, responsive rendering, performance budgets based on observed bottlenecks, lazy media, accessible no-GPU fallback, functional links and data/form behavior.
14. **Critical review:** independent subagents where actually available; otherwise sequential evidence-based role checks, explicitly not independent. Include viewer, customer, copy/SEO, visual, functional and brief fidelity lenses according to scope.
15. **Recover course:** reread original request on major decisions and before handoff; if the site is not right, change concept/content architecture before surface polish, rerender and retest.
16. **Release and handoff:** report what was implemented, verified, remaining UNKNOWN, legally/technically blocked and real deliverables. Don't call a plan a completed site.
17. **Outcome learning:** if deployed, analyze actual search, task success, qualified conversion, abandonment and support tickets when access/consent exists; keep these distinct from screenshot self-review.

## Invisible initiative vs approval boundaries

**Do proactively:** refine language, correct accessible focus, improve genuine on-page metadata, choose more suitable layouts, fix duplicated components, optimize owned visuals, inspect links, create a real meaningful empty state, improve mobile, replace generic decorative motifs, fix factual errors using sources.

**Ask only when blocking or obtain explicit approval:** alter prices/terms, legal claims, data schema, permissions, branding rights, change an explicitly requested subject, fabricate missing testimonials, publish commissioned/copyrighted assets without license, send forms to new endpoints, delete original client work, irreversibly deploy beyond allowed scope.

The agent should **never** justify an inaccurate result with “the prompt was vague.” Its job is to fill reversible professional gaps and make the highest-quality complete deliverable feasible. But no prompt, plugin or evaluator can guarantee the best possible website across every task; actual rendering and controlled human assessment determine whether the ambitions were met.

## Proportionate execution budget

Prefer immediate representative implementation to long speculative reports. Reserve enough work to capture and correct the weakest actual screen. Use specialist references or extra critic roles only if they attack a concrete unknown. Stop when the essential outcome is delivered and real blockers are understood; report limitations without pretending perfection.
